DataDreamer v4.1 planning report

Login-gated Field Guides, without rebuilding an LMS.

This report reconciles the current guide plan with the new product decision: visitors can preview guide value publicly, but starting a guide, reading the full path, and tracking progress require a DataDreamer account.

Executive Recommendation

Recommended model

Public preview, gated reader

Keep `/guides` and `/guides/[slug]` discoverable. Show enough public context to make the guide attractive: title, summary, topics, curator, difficulty, duration, outcomes, and syllabus. Require login for item bodies, external resource URLs, downloads, curator notes, completion toggles, and progress.

Keep it small

One learner collection

Use Directus users plus one `guide_progress` collection. Do not add enrollments, lesson completions, badges, certificates, cohorts, payments, votes, ratings, or a student dashboard in v4.1.

Public vs Logged-In Experience

Public

/guides

Catalogue with guide cards, featured guide, filters, curator metadata, difficulty, estimated duration, and “Sign in to start.”

Public preview

/guides/[slug]

Landing page with guide pitch, outcomes, audience, curator, topics, and syllabus section/item titles. No item body, notes, URLs, embeds, downloads, or progress controls.

Authenticated

Guide reader

Full path, resource links, embeds, curator notes, markdown bodies, completion controls, and resume/progress state from Directus.

Directus Collections

Collection Purpose Public access Guide reader access
guides Top-level Field Guide / learning path. Published preview fields. Published full guide fields.
guide_sections Ordered syllabus groups. Section title and description. Full section data.
guide_items Curated resources and notes. Title/type only for syllabus preview. Body, notes, URLs, assets, embeds, metadata.
guides_topics, guides_specialties, guides_authors Taxonomy and curator relationships. Readable for previews. Readable.
directus_users Accounts for guide readers. No public list/read. User can read own profile through /users/me.
guide_progress One row per user and guide. No access. Create/read/update only where user = $CURRENT_USER.

Progress Shape

Store one record per user and guide. This avoids a noisy per-item completion table while still supporting resume state and account value.

Setup Impact For You

01

Create the reader role

In Directus, add a low-permission guide_reader role. It should not be an admin/editor role. It only needs published guide item reads and own-progress writes.

02

Enable registration carefully

Directus registration is disabled by default. When enabled, all public registrations receive the configured default role. Set that default to guide_reader, not editor/admin.

03

Configure email before password reset

Email signup can work without verification, but password reset and email verification need SMTP and allow-listed frontend URLs.

04

Set CORS and cookies for subdomains

Production spans data-dreamer.net and api.data-dreamer.net. Directus session/cookie settings must allow credentialed auth across the parent domain, and CORS must include production and staging frontend origins.

05

Add Google OpenID if desired

Create Google Cloud credentials, add Directus AUTH_GOOGLE_* env vars, allow public registration, map users to guide_reader, and test staging before production.

Google Login: Pros And Cons

Pros
  • Lowest-friction signup path for people who just want to start a guide.
  • Fewer forgotten-password issues for users who choose Google.
  • Better fit for a premium learning product than a long account form.
  • Directus supports OpenID providers, and Google is a common example.
Cons
  • Requires Google Cloud OAuth setup and separate staging/prod callback testing.
  • Cookie/CORS issues across subdomains can break the flow if configured loosely.
  • Directus users authenticate with the provider they were created with, so account-linking needs deliberate policy later.
  • Email fallback still needs SMTP if you want password reset and verification.

Risks

Auth scope creep

Do not add dashboards, badges, payments, votes, certificates, or item-level pages in this release.

Permission leaks

Public role must not read guide item bodies, notes, resource URLs, files, or progress rows.

SSO configuration

Most risk is operational: callback URLs, cookie domain, CORS credentials, and staging/prod separation.

Sources

Directus supports local email/password plus OAuth 2.0 and OpenID providers, including Google OpenID. User registration is disabled by default and assigns the configured default role when enabled. Directus session login can set an HttpOnly cookie using session mode, and API requests can authenticate with headers or session cookies.
